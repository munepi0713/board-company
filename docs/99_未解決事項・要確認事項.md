## Issue #1: 固定売上の計算式が不明確

**ラベル**: `仕様確認`, `優先度:高`

原文（ページ3）の固定売上の計算式が以下のように記載されている：

```
固定売り上げ＝（知名度＋能力）＋社員数÷10 − 社員数
               10           10
```

社員数に関する項（`+社員数/10` と `-社員数/10`）が相殺されてしまい、社員数が売上に影響しない計算になる。これは意図的なものか、OCR等の読み取りミスか確認が必要。

**暫定対応**: `固定売上 = (知名度 + 能力) / 10 + 社員数 / 10` として実装する。

## Issue #2: 戦闘のダメージ計算式が不明確

**ラベル**: `仕様確認`, `優先度:高`

原文（ページ2）の戦闘公式テーブルが壊れており、正確なダメージ計算式が読み取れない。

記載内容：
```
ダメージ＝攻撃力×すばやさ | 防御力×すばやさ
・社員数、攻撃力・会社評価額
・能力、防御力 | 10 | 5
・知名度、すばやさ
逃げれる確立＝能力＋すばやさ / 300
```

**確認事項**:
1. ダメージ計算で「10」「5」「300」はどこに適用される定数か
2. 攻撃力 = 社員数 + 会社評価額 の正確な計算式（除算の分母は何か）
3. 防御力 = 能力 の正確な対応関係と倍率

**暫定対応**: `ダメージ = (攻撃力 × すばやさ / 100) - (相手防御力 × 相手すばやさ / 100)` として実装する。

## Issue #13: 「10分で遊べる」コンセプトを実現するためのゲーム時間制御メカニズムがない

**ラベル**: `コンセプト改善`, `優先度:高`

現在の仕様ではゲーム終了条件が「全プレイヤーの破産」か「全員合意」のみであり、ゲーム時間を10分以内に収める仕組みがない。いただきストリートには「目標総資産額に到達したら勝利」という明確なゴール設定があり、これによりゲーム時間を制御している。

**改善案**:
1. **目標総資産額による勝利条件**を追加する（例: 総資産10000$到達で勝利）
2. **ターン数上限**を設ける（例: 30ターン上限 → 最も総資産が多いプレイヤーが勝利）
3. ゲーム開始時に「ショートゲーム（10分）」「ロングゲーム（30分）」のモード選択を可能にする
4. 上記パラメータをマップデータ（JSON）に含め、マップごとに異なるゲーム長を設定可能にする

## Issue #14: 戦闘システムが10分ゲームに対して重すぎる

**ラベル**: `コンセプト改善`, `優先度:高`

現在の戦闘システムはRPG風のターン制バトル（攻撃/防御/カード/逃走のコマンド選択、HP削り合い）であり、1回の戦闘に数分かかる可能性がある。10分のゲーム中に戦闘が2〜3回発生すれば、それだけでゲーム時間の大半を消費してしまう。

**改善案**:
1. **自動解決方式**: 戦闘パラメータから勝敗を一発判定し、結果をアニメーションで演出する（プレイヤーの操作不要）
2. **ワンアクションバトル**: 攻撃/防御/カード/逃走から1回だけ選択して即決着する方式にする
3. **戦闘省略オプション**: 「使用料を支払って戦闘を回避する」選択肢を追加する（いただきストリートの買い物料に相当）
4. 上記を組み合わせ、デフォルトは使用料支払いとし、任意で戦闘を仕掛けられる仕組みにする

## Issue #15: ボードサイズが10分ゲームに対して大きすぎる可能性

**ラベル**: `コンセプト改善`, `優先度:中`

現在の仕様では本線32マス＋分岐8マスの計約40マスだが、1d6（平均3.5マス）で4人が周回するには広すぎる。10分間（約15〜20ターン）では各プレイヤーがボードを1〜2周する程度であり、土地の取り合いや会社建設が十分に発生しない可能性がある。

**改善案**:
1. ショートゲーム用に**16〜20マス**程度のコンパクトなマップを用意する
2. マップデータはJSONプラグイン構造で外部化されているため、複数マップを用意して選択可能にする
3. サイコロを2個（2d6、平均7マス）にするオプションを追加してテンポを上げる

## Issue #16: CPU行動のテンポ・演出速度に関する仕様がない

**ラベル**: `コンセプト改善`, `優先度:高`

4人対戦時、CPUプレイヤー3人の行動（移動、土地購入判断、会社建設判断、戦闘、経営判断）が毎ターン発生する。これらの演出をすべて表示すると、人間プレイヤーの待ち時間が長くなり10分では遊びきれない。

**改善案**:
1. **CPU行動の高速モード**: CPUの移動・判断をアニメーション短縮または省略して表示する
2. **スキップ機能**: ボタン（Space等）でCPUターンの演出をスキップできるようにする
3. **一括表示**: CPUの行動結果をまとめてテキストで表示する（「Aが土地を購入」「Bが会社を建設」等）
4. UI仕様（09_UI画面設計.md）にCPU演出の速度設定を追加する

## Issue #17: 会社経営の意思決定量が10分ゲームに対して多すぎる

**ラベル**: `コンセプト改善`, `優先度:中`

18種類の会社×5つの経営コマンド（社員教育・広告・雇用・解雇・清算）は、スキマ時間向けゲームとしては意思決定のオーバーヘッドが大きい。自分の会社マスに止まるたびに経営判断が求められると、テンポが悪くなる。

**改善案**:
1. 会社の種類を**8〜10種類**程度に絞る（ショートゲーム用）
2. 経営コマンドを**投資（能力・知名度UP）/雇用/清算**の3つに簡略化する
3. 経営画面を省略し、自動で最適な経営判断を提案する「おまかせ経営」オプションを追加する
4. 会社パラメータの減衰（偶数ターン毎に能力・知名度-2）を緩和またはショートゲームでは無効にする
